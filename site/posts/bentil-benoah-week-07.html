My classifier prompt is short enough to copy into another tool. I thought that would make switching simple. The local test showed that getting the same kind of answer back is another question.

I am looking at a hypothetical Belgian SME using Odoo. The classifier sorts enquiries into five groups: Order Status, Invoice/Payment, Return/Refund, Product Issue and Other. So far, my Build is a prompt prototype. Connecting it to Odoo is still a plan.

Using the decision framework, I would start with Buy. Sorting enquiries helps staff do their work. The company competes through its products and customer relationships. Classification is a common task with existing solutions, so question two points to Buy. I would still test whether a product fits before choosing it. There is no evidence yet that this SME needs several AI capabilities or big changes within twelve months. Building its own model would bring maintenance work it has not justified. If it needs an Odoo connection, a small adapter could help it change providers later.

My provisional lock-in score for the cloud prototype is 7/15. Data portability gets 1 because my prompt and tests are Markdown files. ChatGPT also documents a conversation export, but I have not tried it. Service stability gets 2 because the Europe Terms do not promise to keep the service in its current form. Pricing gets 2: subscription rises come with thirty days' notice, but there is no long-term fixed price. Feature dependency gets 2 because the local replies were very different. Migration cost gets 0 for this small prototype, using the two-day estimate below. These scores describe what I have tested so far. A deployed Odoo system would need its own assessment. OpenAI Europe Terms · Data export documentation

Codex ran my ten synthetic enquiries twice on Llama 3.2 3B through Ollama. In each run, only 2/10 replies matched the exact category name the prompt asked for. The Week 2 cloud log records 10/10 in both runs. That gives an 80 percentage-point gap under this strict rule. The dates and interfaces differ, which limits the comparison. Many local replies were category numbers. For the double-payment enquiry, the first reply was “1. Order Status” and the second was “2”. Both the format and consistency need work.

There was no local inference provider fee. I still have to account for the computer, power and maintenance. The historical cloud test cost is unknown. My Week 6 estimate of $0.000018 per call uses an assumed output count, so it cannot stand in for a measured bill.

I estimate sixteen hours at an assumed €50/hour, giving €800, to prepare and check a prototype switch. That includes the connector, validation, testing and handover. Production would need a separate estimate.

In week one, I would save the evidence and reject invalid labels. In month one, I would build the adapter and try harder enquiries. By day ninety, I would rehearse the switch and compare errors before changing a live workflow. Keeping the prompt is useful, but I also need evidence that the replacement model can do the job.
