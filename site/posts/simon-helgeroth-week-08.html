AI Integration for a Mid-Sized Nordic Staffing Agency: A €35K Design

Most staffing agencies adding AI skip the architecture phase. They buy an expensive ATS add-on or paste job ads into a chatbot without checking where candidate data goes or how errors get fixed. When companies skip design, they end up with hidden labor costs from fixing bad AI outputs and high switching costs. Here is what a realistic integration looks like for a recruitment company.

NordicStaff AB is a 95-employee staffing and recruitment agency based in Gothenburg, Sweden, generating €14M in annual revenue. The agency publishes roughly 350 job advertisements per month across engineering, IT, and administration. They currently use Teamtailor as their Applicant Tracking System (ATS), Microsoft 365 for internal communication, and a legacy SQL database for client contracts. Their total Year 1 budget for AI is €35,000, with a 2-month implementation timeline. The goal is to automate factual quality checks on draft job ads before publication—catching missing start dates, locations, or employment percentages—without slowing down recruiters.

The system follows a simple five-layer design costing €22,400 in Year 1 setup and €2,380/year in running costs, staying well within the €35,000 budget. In the data layer, draft job ads are pulled from Teamtailor via its standard REST API when a recruiter marks a draft "Ready for review," while client metadata is read from a read-only SQL view to verify contract terms, keeping all candidate PII untouched inside Teamtailor. For the AI layer, we use Google's gemini-3.1-flash-lite API ($0.25 per 1M input tokens, $1.50 per 1M output tokens, AI Pricing Reference, 7 September 2026) running on a Zero Data Retention EU endpoint. Using a strict, bounded extraction prompt based on my Version 2 Build (which extracts 7 standardized factual fields at 67% accuracy), the model checks start date, application deadline, work location/mode, employment extent, languages, experience, and must-have vs. nice-to-have separation. At ~930 tokens per run and 350 ads/month, API token spend is under €0.25/month. In the integration layer, lightweight Python middleware hosted on an EU cloud server (€80/month) handles API calls, strips any accidental personal names before sending text to the LLM, and parses the JSON response. In the interface layer, instead of forcing recruiters into a new dashboard, the extracted 7-field checklist posts directly back as an internal note in Teamtailor and sends a quick alert in Microsoft Teams if any mandatory field is marked "Missing." Finally, in the governance layer, every prompt and response is logged locally for 90 days, a recruiter always reviews and approves the final text, and if the API goes down, recruiters simply publish ads using their existing manual checklist.

Why not use Teamtailor's built-in AI features? Built-in ATS tools focus on generating generic ad text rather than enforcing agency-specific compliance rules across 7 strict fields, and storing custom logic inside a vendor's workflow builder increases lock-in. By keeping our prompt as a plain-text file in our own Python middleware, lock-in risk is low—we can switch to OpenAI or Mistral in under one day, and major commercial models sit within a factor of two of each other on token pricing (AI Pricing Reference, 7 September 2026). As for cost at scale: even if NordicStaff grows 3x to 1,050 job ads per month, token costs rise to just €0.75/month. The real cost is human error remediation—at a 33% error rate (347 minor flags to double-check) taking 2 minutes per fix at €44/hr, human review costs roughly €509/month, which still fits easily inside budget and beats manual checking from scratch.

The one thing I am least sure about is where to draw the line between regex rules and the LLM: could simple keyword rules handle half of these 7 fields (like employment percentage and deadlines) for free, leaving the AI only for trickier fields like work location and experience?
